# MealNoteDiaryBot

## Расположение файлов

В корневой папке `MealNoteDiaryBot` находятся `bot`, `Отчет.docx` и `Видеообзор.mp4`. Исходный код, скрипты запуска, `.env`, виртуальное окружение и хранилища перенесены в `bot`. Предыдущие версии видео сохранены в `bot/video`, изображения отчёта — в `bot/report-assets`.

Для запуска откройте `bot/start_telegram.cmd`. Все команды ниже выполняются из `MealNoteDiaryBot/bot`; если терминал открыт в корне проекта, сначала выполните `cd .\bot`. В Obsidian открывайте `MealNoteDiaryBot/bot/vault`.

Персональный помощник для дневника питания: Python, локальная языковая модель Ollama, Telegram Bot API и хранилище Obsidian.

Работа подготовлена по заданию «Проектирование базы знаний в Obsidian и подключение агента искусственного интеллекта через Telegram». Программа принимает факт еды, уточняет дату или блюда, читает дневник и меняет график только после явного подтверждения. Автоматические тесты по просьбе пользователя не создавались.

## Готовность

- Реализованы ядро, локальный диалог, Telegram long polling, постоянное хранилище и инструкция подключения.
- `vault-demo` содержит учебные сообщения и события; `demo/transcript.json` — фактические ответы приложения с настоящей локальной моделью. Учебные даты сообщений задаются входным файлом, время сохранения берётся с компьютера.
- Telegram-бот подключён; реальная переписка показана в отчёте и итоговом видеообзоре. Токен и ID владельца хранятся в локальном `.env`.
- `vault` — рабочее хранилище подключённого бота; `vault-demo` используется отдельно для локальных примеров.
- GitHub-публикация не выполнялась. Исходники и учебная база подготовлены к размещению; не публикуйте личный `vault` и `.env`.

## Среда

Python 3.11 или новее. Фактический запуск: Python 3.12.14, Windows x64, Ollama 0.40.17, модель `qwen3:4b`. Единственная pip-зависимость — `tzdata==2026.6`, необходимая для `zoneinfo` в Windows. HTTP, JSON, файловая система, CLI и обработка дат используют стандартную библиотеку Python. Веса модели не включены в архив проекта.

В папке проекта также подготовлена `.venv` с установленным на компьютере Python 3.14.3. Для запуска двойным щелчком используйте `start_console.cmd`; `start_telegram.cmd` запускает Telegram после заполнения `.env`. На другом компьютере сначала выполните `setup.cmd`. В архив `.venv` не включена.

## Быстрый локальный запуск

В PowerShell из папки `MealNoteDiaryBot/bot`:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --no-index --find-links wheels -r requirements.txt
ollama pull qwen3:4b
.\.venv\Scripts\python.exe main.py console --demo
```

Ollama должна быть запущена. Если настольное приложение Ollama не запущено, в отдельном окне выполните `ollama serve`. При иной установленной модели скопируйте `.env.example` в `.env` и измените `OLLAMA_MODEL`. Первое обращение включает загрузку модели в память.

В `wheels` приложена официальная дистрибуция tzdata 2026.6 с PyPI вместе с её лицензией. Команда установки выше работает без обращения к PyPI. Для первоначального скачивания весов Ollama требуется интернет; после этого интерпретация работает локально.

Команды в локальном диалоге: `/help`, `/today`, `/yesterday`, `/plan`, `/answer текст`, `/new`, `/confirm ID`, `/cancel ID`, `/exit`. Можно писать обычным языком, например «Сегодня на завтрак в 08:30 ел овсянку и банан».

## Подключение Telegram

1. В Telegram откройте официального `@BotFather`, отправьте `/newbot`, задайте имя и уникальный username. Сохраните выданный токен только локально.
2. Получите собственный числовой Telegram user ID. Без сторонних ботов: создайте `.env` с токеном, отправьте своему боту `/start`, затем выполните `python telegram_id.py`. Скрипт выводит только ID отправителей личных сообщений и не подтверждает обновления. Сверьте ID со своим сообщением; бот в это время должен быть остановлен.
3. В PowerShell выполните `Copy-Item .env.example .env` (если `.env` уже существует, отредактируйте его, не перезаписывая). Заполните `TELEGRAM_BOT_TOKEN` и `ALLOWED_USER_ID`. `user ID` проверяет отправителя, `chat ID` нужен для адреса ответа — это разные поля API.
4. Выполните `.\.venv\Scripts\python.exe main.py init`, затем `.\.venv\Scripts\python.exe main.py telegram`.
5. Напишите боту `/help`, факт еды с днём, затем «Что я сегодня ел?». Откройте папку `vault` как существующее хранилище в Obsidian и сопоставьте карточку с исходным сообщением.

Нужны только личные текстовые сообщения выбранного владельца. Группы, каналы, изменения старых сообщений, файлы и голосовые сообщения не обрабатываются. Новое сообщение, даже с тем же текстом, является новым фактом. Ответы отправляются лишь после сохранения. При ошибке модели обновление Telegram остаётся неподтверждённым и будет повторено после восстановления. При постоянной ошибке остановите бота и исправьте настройки. Если ранее был настроен webhook, отключите его перед long polling средствами Bot API.

Пример `.env` без секретных значений — `.env.example`. Не отправляйте токен в чат, не вставляйте в отчёт и не сохраняйте его в Git.

В Telegram ответы оформляются в MarkdownV2: разделы выделены жирным, команды и время — моноширинным шрифтом, между смысловыми блоками оставлены пустые строки. Текст пользователя экранируется; длинный ответ разбивается на самостоятельные сообщения с закрытой разметкой. После обновления кода перезапустите `start_telegram.cmd` и отправьте новый `/help`: уже отправленные сообщения Telegram не меняются.

## Устройство проекта

- `main.py` — команды запуска и локальный разговор.
- `mealbot/config.py` — `.env` и параметры.
- `mealbot/model.py` — системные правила, JSON Schema, HTTP-интеграция Ollama, проверка ответа.
- `mealbot/service.py` — разрешённые операции, даты, уточнения, дневник, предложения изменения графика.
- `mealbot/storage.py` — снимок состояния, блокировка процесса и Markdown-проекция.
- `mealbot/telegram.py` — long polling, доступ по отправителю, отправка и сохранение offset.
- `mealbot/formatting.py` — оформление ответов Telegram в MarkdownV2: заголовки, команды, даты, экранирование и разделение длинных сообщений.
- `telegram_id.py` — локальное получение user ID без печати токена.
- `demo/conversation.jsonl` — учебные реплики для последовательного воспроизведения.
- `demo/transcript.json` — сохранённые ответы реального запуска.

## База знаний Obsidian

```text
vault-demo/                    vault/ — личная база той же структуры
  index.md                     навигация и ссылки на все события
  profile/user.md               student, владелец, Europe/Moscow
  plans/meal-plan.md            завтрак 08:30, обед 13:00, ужин 19:00 изначально
  events/YYYY-MM-DD/meal-*.md   фактические события
  sources/src-*.md              исходный текст, идентичность и интерпретация
  summaries/YYYY-MM-DD.md       производные дневные сводки
  proposals/*.md               состояния предложений изменения графика
  dialogues/pending.md         незавершённое уточнение
  rules.md                     правила хранения
  .agent/state.json            полный атомарный снимок состояния
```

Событие связано с профилем, дневной сводкой и всеми источниками через wikilinks. Неизвестные поля — `null`; в тексте — «неизвестно». Количество сохраняется только если оно сообщено; калорийность не рассчитывается. `meal_time`, `sent_at`, `recorded_at` имеют разный смысл. Дата определяется в часовом поясе профиля по timestamp исходного сообщения, а не по моменту обработки. Явная дата имеет приоритет над «сегодня». График хранит план, а события — факты.

Откройте в Obsidian **папку целиком**, включая вложенные каталоги. В отчёт включены реальные фрагменты переписки Telegram, соответствующая карточка события и граф связей рабочего хранилища.

## Уточнения и изменение графика

«Я сегодня покушал» сохраняет источник и незавершённый черновик, но не событие. Ответ `/answer Ел суп` дополняет именно этот черновик и создаёт одно событие со ссылками на оба сообщения. После полуночи уже определённая дата остаётся прежней; явное исправление пользователем её меняет. Только `/answer` считается уточнением, новый обычный запрос не присоединяется к черновику. `/new` закрывает черновик. Просмотр дневника и графика доступен и во время уточнения.

«На днях ел суп» требует дату. «Завтра поем суп» не создаёт события. Для нескольких приёмов пищи в одном сообщении бот предлагает отдельные записи. Время, тип приёма и количество необязательны.

«Перенеси ужин на 19:30» создаёт предложение с уникальным ID. До `/confirm ID` график остаётся прежним; `/cancel ID` закрывает предложение. Завершённый ID не применяется повторно. Пока одно предложение ожидает решения, новое отклоняется с указанием действующего ID. Команды подтверждения обрабатывает приложение, модель их не выполняет. График не меняет события.

## Сохранность и ограничения

Все сведения находятся внутри vault. Единственный фиксируемый атомарно источник состояния — `.agent/state.json`; Markdown — восстанавливаемая читаемая проекция. Снимок сначала записывается во временный файл на том же диске, сбрасывается через `fsync` и заменяется `os.replace`. Затем каждый Markdown-файл заменяется атомарно. При прерывании обновления Markdown снимок остаётся полным; следующий запрос или `python main.py export --demo` восстанавливает проекцию до ответа. Это не общая атомарная транзакция для всех Markdown-файлов: во время экспорта Obsidian может кратковременно видеть смешанную ревизию. До завершения проекции успех не подтверждается.

Блокировка `.agent/process.lock` исключает одновременную запись нескольких процессов в одну базу. Не запускайте два отдельных Telegram poller даже с разными vault для одного токена. Для независимых владельцев используйте отдельные базы и токены. Снимок целиком хранится в памяти и перезаписывается: решение рассчитано на небольшую персональную учебную базу. Несанкционированное чтение файлов на компьютере средствами ОС не входит в модель защиты бота.

Ключ повторной обработки: `transport + chat_id + message_id`. В снимке вместе фиксируются источник, событие, черновик, предложение и готовый ответ. Повтор того же сообщения возвращает сохранённый ответ. Для Telegram offset сдвигается после сохранения и отправки ответа. При обрыве сети после фактической доставки возможен повтор ответа, но не повтор события. Разные ID с одинаковым текстом не объединяются.

Чтение ответа выполняется по свежему снимку на диске; модель выбирает операцию, приложение само выбирает события и формирует точный ответ без сочинения продуктов. Внешнее ручное редактирование Markdown не меняет данные бота: проекция перезаписывается. Профиль и пояс изменяют в `.agent/state.json` при остановленном приложении, затем выполняют `export`. До правок сделайте резервную копию. Копируйте весь vault вместе со скрытой `.agent`, предварительно остановив бота. Облачная синхронизация и одновременная работа с нескольких устройств не настроены; все компоненты предполагаются на одном компьютере.

## Воспроизведение учебного разговора

```powershell
.\.venv\Scripts\python.exe main.py script --demo --input demo\conversation.jsonl --output demo\transcript.json
```

Повторный запуск на поставляемом `vault-demo` возвращает сохранённые ответы для прежних ID. Чтобы снова обратиться к модели с чистой базой, задайте новый каталог, например `--vault vault-demo-new`; не удаляйте имеющуюся базу. JSONL содержит учебные timestamp, включая переход через полночь, а не время реального сообщения Telegram. Демонстрация — не автоматический набор тестов: нет `pytest`, `unittest`, assert или автоматической оценки результатов.

Разместить исходники и `vault-demo` в своём GitHub-репозитории, если этого требует преподаватель. Учётные записи, токен и репозиторий пользователя автоматически не создавались.
